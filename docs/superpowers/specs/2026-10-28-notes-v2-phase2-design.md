# 筆記 App v2 — 第 2 階段「匯入匯出」設計規格

- 日期：2026-10-28
- 狀態：待審閱（第 15 節有 6 個待確認事項）
- 前置：第 1 階段規格 `2026-10-21-notes-v2-phase1-design.md`（第 2.1、12、14 節的決策沿用，本文不重述）；第 1 階段已完成，另已加入附件管理（附件面板、附件垃圾桶）
- 範圍：v1 資料遷移、Markdown 匯出、Markdown 匯入、自動鏡像 `.md`，以及切換到正式網址的流程

---

## 1. 目標與成功標準

1. **v1 使用者無痛搬家**：在正式網址第一次打開 v2，v1 的筆記、資料夾、附件、連結、標籤全部自動出現；v1 原始資料一個位元都不改
2. **資料帶得走**：任何時候都能把整個知識庫匯出成一般 Markdown ZIP，用其他編輯器（Obsidian、VS Code、Typora）打開仍可讀
3. **有一份隨時更新的檔案副本**：Chrome / Edge 桌面版可指定一個資料夾，App 自動把筆記寫成 `.md`，作為瀏覽器資料被清除時的保險
4. **帶得回來**：v2 自己匯出的 ZIP 再匯入，內容、資料夾、連結、區塊連結、附件完全還原（往返不失真，限第 6.4 節列出的已知損失）

品質門檻：

| 項目 | 門檻 |
|---|---|
| v1 遷移（1,000 篇、200 個附件、合計 500 MB） | 完成且 App 全程可用；遷移中可編輯已搬好的筆記 |
| 匯出 1,000 篇（不含附件） | < 5 秒，不凍結畫面（背景執行緒） |
| 鏡像 | 停止輸入後 ≤ 3 秒寫入檔案；打字時不做任何檔案存取（沿用第 1 階段「不在按鍵中做事」原則） |
| 往返測試 | 第 6 節所有支援格式：匯出 → 匯入 → 再匯出，兩次 `.md` 逐字相同 |

## 2. 範圍

### 2.1 包含
- **v1 自動遷移**：同網址下讀取 v1 的 `WebObsidianDB` + `localStorage` 的自訂資料夾
- **v1 備份檔匯入**：讀取 v1 匯出的 ZIP（`manifest.json`，`format: markdown-vault-zip`，`version: 3`）。用途：切換前就能在 Vercel 預覽網址試遷移（不同網址讀不到 v1 的 IndexedDB），以及切換當天的保險
- **匯出**：整個知識庫 / 單一資料夾 / 單篇筆記 → ZIP 或 `.md`
- **匯入**：`.md` 檔、整個資料夾、ZIP（一般 Markdown 與 v2 匯出格式）
- **自動鏡像 `.md`**：單向 App → 資料夾，Chrome / Edge 桌面版
- **設定頁「資料」分頁**擴充：匯入、匯出、鏡像狀態、遷移報告
- **切換流程**（第 13 節）

### 2.2 不包含
- 外部修改 `.md` 自動回寫（沿用第 1 階段決策；但外部修改不會被默默覆蓋，見 8.5）
- 匯出 PDF（第 4 階段分享）
- Notion / Evernote 等其他 App 的專屬格式（只吃一般 Markdown）
- 數學公式、Mermaid 的**顯示**（第 5 階段）；本階段只保證這些內容**不遺失**

## 3. 架構

沿用第 1 階段分層。新增：

```
src/
  core/markdown/        純 TypeScript，不碰 DOM，可在背景執行緒跑
    serialize.ts        ProseMirror JSON → Markdown 文字
    parse.ts            Markdown 文字 → ProseMirror JSON（markdown-it token 直接轉，不經 HTML）
    v1-dialect.ts       v1 專屬語法擴充（::: quote、> [!callout]、==螢光==、![[媒體]]、a./i. 清單…）
    paths.ts            標題 ↔ 檔名、資料夾路徑、衝突處理
  core/transfer/
    export.ts           知識庫 → 檔案清單（路徑 + 內容），與 ZIP / 資料夾無關
    import.ts           檔案清單 → 知識庫（兩階段：先建筆記與資料夾、再解析連結）
    migrate-v1.ts       v1 資料 → 檔案清單形式的中間格式 → 共用 import 管線
  core/mirror/          鏡像排程、比對、衝突處理
  adapters/fs/          目錄介面：FileSystemAccess 實作、OPFS 實作（測試用）、記憶體實作
  adapters/zip/         fflate 包裝（串流讀寫）
  adapters/v1/          讀 WebObsidianDB（唯讀）、讀 v1 ZIP
  workers/transfer      匯出、匯入解析在背景執行緒
  features/settings/    DataSection 擴充、MigrationReport
```

原則：
- **一條轉換管線**：v1 IndexedDB、v1 ZIP、一般 Markdown、v2 ZIP 最後都轉成同一個「檔案清單」中間格式（`{ path, text | blob, meta? }[]`），再走同一個 `import.ts`。遷移不另寫一套
- `core/markdown` 不依賴 DOM（現有的貼上功能用 `markdown-it → HTML → DOMPurify → Tiptap`，本階段改為共用 `parse.ts`，貼上與匯入行為一致）
- ZIP 用 **fflate**（體積小、可串流，不必整包載入記憶體）

## 4. v1 資料遷移

### 4.1 v1 資料來源（已查 `v1-archive` 分支確認）

| 來源 | 內容 |
|---|---|
| IndexedDB `WebObsidianDB` v1，store `notes` | `{ id, title, content(Markdown), folder?("a/b" 路徑), tags[], outlinks[], createdAt, updatedAt(ISO 字串) }` |
| store `media` | `{ id, filename, mimeType, blob, size, createdAt }`；內文以 `![[id|顯示名稱]]` 或舊版 `![[檔名]]` 引用 |
| `localStorage["obsidian_custom_folders"]` | 空資料夾也要保留的資料夾路徑清單 |
| v1 ZIP | `manifest.json`（`notes[]`、`media[]`、`customFolders[]`）+ `notes/{id}.md` + `media/{id}/{檔名}` |

### 4.2 何時觸發
- 啟動時（在第一次畫面之後、背景執行），若同時成立：同網址存在 `WebObsidianDB`、`meta.v1Migration` 不是 `done`
- 若 v2 知識庫已有使用者自己建立的筆記（不是歡迎筆記或功能導覽），**不自動遷移**，改在設定頁顯示「發現舊版資料，要匯入嗎？」，由使用者決定（避免兩邊都用過時混在一起）
- 設定頁「匯入 v1 備份 ZIP」隨時可用

### 4.3 流程
1. **唯讀讀取**：只開 v1 資料庫讀取，絕不寫入或刪除；v1 資料本身就是備份。第 2 階段任何程式都不刪 `WebObsidianDB`
2. **事前檢查**：估算所需空間（附件總和 × 1.1），`navigator.storage.estimate()` 不足時先提示，不開始
3. **建立資料夾**：由 `folder` 路徑與自訂資料夾清單建出巢狀資料夾
4. **逐篇轉換**：v1 Markdown → v2 區塊（第 5 節對照表），一篇一個交易；附件逐一搬（一次只載入一個 blob）
5. **解析連結**：全部筆記建好後，第二輪把 `[[標題]]`、`[[標題#標題段落]]` 換成筆記連結 / 區塊連結
6. **完成**：寫入 `meta.v1Migration = { status: 'done', at, report }`，顯示遷移報告

### 4.4 中斷與重來
- 進度記在 `meta.v1Migration = { status: 'running', map: { v1Id → v2NoteId }, mediaMap: { v1MediaId → attachmentId } }`，每篇完成即更新
- 中途關閉：下次啟動從未完成的那篇繼續，已搬的不重搬（以 `map` 判斷）
- 遷移中途建立的筆記立即可見、可編輯；第二輪連結解析只改「還是純文字 `[[…]]`」的地方，不動使用者已經改過的內容

### 4.5 衝突與資料修正
| 情況 | 處理 |
|---|---|
| v1 有同名筆記（v2 不允許） | 較晚建立者加「 (2)」，記入報告 |
| 標題空白 | 「未命名」，同名依上規則 |
| `[[不存在的筆記]]` | 保留為純文字 `[[不存在的筆記]]`，記入報告（v2 的連結不能指向不存在的筆記） |
| `![[x]]` 找不到附件 | 段落中留「（找不到附件：x）」，記入報告 |
| SVG 附件（v2 基於安全不收 SVG） | 轉成 PNG 後存入；原 SVG 不保留 |
| 非圖片影片附件（PDF、音訊、Office 檔…） | 見待確認 #1 |
| 時間 | `createdAt`、`updatedAt` 沿用 v1，排序依 v1 的修改時間 |

### 4.6 遷移報告
設定頁「資料」顯示：搬了幾篇、幾個資料夾、幾個附件；改名清單；未解析連結清單（可點擊前往該筆記）；轉成純文字的語法清單。報告保留在 `meta`，隨時可再看。

## 5. Markdown → 區塊（匯入與 v1 遷移共用）

| Markdown | v2 |
|---|---|
| `#`～`###` | 標題 H1～H3；`####` 以下 → H3 |
| 段落、`**粗**`、`*斜*`、`~~刪~~`、`` `碼` ``、`[文字](網址)` | 對應段落與格式 |
| `==螢光==` | 螢光標記（預設色） |
| `<u>文字</u>` | 底線（第 6 節自己匯出的格式，唯一認得的 HTML 之一） |
| `- ` / `1.` / `- [ ]` / `- [x]` | 項目 / 編號 / 待辦清單，含巢狀 |
| v1 的 `a.`、`i.` 編號 | 編號清單 + `listStyle: alpha / roman` |
| `>` | 引用 |
| `:::quote … :::`（v1） | 引用 |
| `> [!note]`、`[!info]` / `[!tip]`、`[!success]` / `[!warning]`、`[!caution]`、`[!danger]`、其他 | 提示框：info / tip / warning；其他 → info；callout 標題 → 提示框第一行粗體；可摺疊標記（`+` / `-`）捨棄 |
| ```` ```lang ```` | 程式碼區塊（含 ABAP） |
| ```` ```mermaid ```` / `$$…$$` / `$…$` | 保留原文：程式碼區塊（語言 `mermaid` / `math`）、行內碼。第 5 階段再顯示成圖與公式 |
| GFM 表格 | 表格；儲存格內 `<br>` → 換行（另一個認得的 HTML） |
| `---` | 分隔線 |
| `![](相對路徑)`、`![[檔名]]`、`![[檔名\|寬度]]` | 圖片 / 影片區塊（路徑在匯入的檔案中找）；找不到 → 純文字並記入報告 |
| `[[標題]]`、`[[標題#段落標題]]`、`[[標題#^區塊id]]` | 筆記連結 / 區塊連結；`[[標題\|別名]]` 見待確認 #2 |
| `#標籤` | 標籤 |
| 註腳 `[^1]` | 文末加「註腳」段落，引用處保留 `[^1]` 文字（註腳不做，但內容不丟） |
| `~下標~`、`^上標^`、其他 HTML | 純文字保留（第 1 階段 2.1 決策） |
| YAML frontmatter | 不顯示；其中 `tags:` 轉為文末標籤，`created` / `updated` 若有則作為時間 |

## 6. 區塊 → Markdown（匯出與鏡像共用的「新格式」）

### 6.1 基本規則
- 一篇筆記一個檔，檔名即標題，**內文不重複寫標題**
- 不寫 frontmatter（保持乾淨，任何編輯器都能直接讀）；建立 / 修改時間寫入檔案系統時間（ZIP 內為 entry 時間）
- 文字採 CommonMark + GFM，必要的特殊字元跳脫（避免匯出的 `*`、`#`、`[[` 被誤認成語法）

### 6.2 對照
| v2 | Markdown |
|---|---|
| 標題、段落、粗斜刪碼、網址連結 | 標準語法 |
| 底線 | `<u>…</u>` |
| 螢光標記 | `==…==`（顏色不保留） |
| 文字顏色 | 不輸出（見 6.4） |
| 清單、待辦、巢狀 | 標準語法，縮排 2 格（有序清單 3 格） |
| 編號樣式 alpha / roman | 仍輸出 `1.`（Markdown 無此語法） |
| 引用 | `>` |
| 提示框 | `> [!info]` / `[!tip]` / `[!warning]` + 內容 |
| 程式碼 | ```` ```lang ```` |
| 表格 | GFM 表格；儲存格內換行 → `<br>`；欄寬不保留 |
| 圖片 / 影片 | `![檔名](相對路徑)`，路徑指向 `附件/` |
| 筆記連結 | `[[標題]]` |
| 區塊連結 | `[[標題#^區塊id]]`，並在**被連結的那個區塊**行尾加 ` ^區塊id`（Obsidian 慣例，Obsidian 可直接跳轉）；沒被連結的區塊不加 |
| 標籤 | `#標籤` |
| 分隔線 | `---` |

### 6.3 ZIP 結構
```
知識庫名稱-2026-10-28.zip
├── 資料夾A/
│   ├── 子資料夾/筆記.md
│   └── 另一篇.md
├── 根目錄的筆記.md
├── 附件/
│   ├── 範例圖片.png
│   └── 範例圖片 (2).png      ← 同名附件自動編號
└── .notes-v2.json            ← 選擇性 manifest（見下）
```
- `.notes-v2.json`：記錄 noteId、區塊 id 對照、附件 id、資料夾排序與空資料夾。**只給 v2 匯回時用**，讓往返保留原 id（反向連結、區塊連結不斷）。其他編輯器會忽略這個隱藏檔
- 垃圾桶內的筆記與附件不匯出；未被任何筆記使用的附件預設不匯出（可勾選「包含未使用的附件」）

### 6.4 已知損失（往返後無法還原，匯出時在對話框說明一次）
文字顏色、螢光標記顏色、表格欄寬、圖片寬度、編號清單的 alpha / roman 樣式。若匯回時帶有 `.notes-v2.json`，以上全部可還原（manifest 內存這些屬性）。

### 6.5 檔名規則（`paths.ts`）
- 移除 `/ \ : * ? " < > |` 與控制字元；去掉結尾的 `.` 與空白；Windows 保留名（`CON`、`NUL`…）加底線
- 長度上限 120 字元（以 UTF-8 位元組計，避免 Windows 路徑過長），超過截斷
- 空標題 → `未命名`
- 清理後同一資料夾撞名（例如 `a/b` 與 `a:b`）→ 加 ` (2)`

## 7. 匯入（一般 Markdown 與 v2 ZIP）

### 7.1 入口
設定 →「資料」→「匯入」：選 `.md` 檔（可多選）、選資料夾、選 ZIP；也支援把檔案直接拖進側欄。

### 7.2 流程
1. 背景執行緒讀取並解析，顯示**預覽**：將建立幾篇、幾個資料夾、幾個附件；重名會如何處理；有哪些連結找不到
2. 匯入目的地：知識庫根目錄或指定資料夾（預設建立「匯入 2026-10-28」資料夾，避免和現有筆記混在一起）
3. 確認後寫入；兩輪處理（先建筆記與附件、再解析連結），可中斷續傳（同 4.4 的進度紀錄方式）
4. 完成後顯示報告（同 4.6）

### 7.3 規則
- 標題 = 檔名（去 `.md`）；與現有筆記重名 → 加「 (2)」
- 連結解析優先找同批匯入的筆記，其次現有筆記
- 帶 `.notes-v2.json` 且 noteId 在知識庫中已存在（例如匯回自己的備份）→ 見待確認 #3
- 單一附件上限 100 MB（同第 1 階段）；`.md` 以外、非圖片影片的檔案略過並列入報告

## 8. 自動鏡像 `.md`

### 8.1 設定
設定 →「資料」→「同步到資料夾」→ 選擇資料夾（`showDirectoryPicker`）。資料夾 handle 存在 IndexedDB `meta`。不支援的瀏覽器（Safari、Firefox、手機）顯示「此瀏覽器無法自動同步到資料夾，請使用匯出」。

### 8.2 權限
瀏覽器每次重新開啟後需要使用者再按一次才能恢復寫入權限。啟動時若權限狀態為 `prompt`，側欄底部「已儲存在此裝置」旁出現「資料夾同步已暫停 · 繼續」，點一下即恢復；不彈對話框打擾。

### 8.3 寫入時機
- 筆記：indexer 完成該篇索引後（已在停止輸入約 1 秒、閒置時間）排入鏡像佇列，再於閒置時間寫檔
- 改名、移動資料夾：新路徑寫入後刪除舊檔
- 附件：第一次被筆記使用時寫入 `附件/`
- 啟動後背景比對一次（`meta.mirror` 存每篇的 `{ path, hash, mtime }`），補寫離線期間的變更
- 檔案內容與 6.x 匯出格式**完全相同**；資料夾裡不放 `.notes-v2.json` 以外的隱藏檔（manifest 同樣寫入，供日後從資料夾還原）

### 8.4 刪除
見待確認 #4。

### 8.5 外部修改不覆蓋
寫入前比對檔案目前的修改時間 / 大小與上次寫入時記錄的值。不同 → 表示使用者在外部改過：外部版本改名保留為 `標題 (外部修改 2026-10-28 1432).md`，再寫入 App 版本，並在設定頁提示。不自動合併、不回寫進 App（第 1 階段決策）。

### 8.6 錯誤
| 情況 | 處理 |
|---|---|
| 資料夾被刪除或改名 | 鏡像暫停，設定頁顯示「找不到資料夾，請重新選擇」 |
| 權限被撤銷 | 同 8.2 的暫停狀態 |
| 磁碟空間不足 / 寫入失敗 | 重試三次後暫停該篇，設定頁列出 |
| 同時開多個分頁 | 用 Web Locks（`navigator.locks`）確保只有一個分頁在寫，避免互相覆蓋 |

## 9. 從資料夾或 ZIP 還原整個知識庫

資料遺失時的救援路徑：設定 →「資料」→「從備份還原」，選 v2 匯出的 ZIP 或鏡像資料夾。與一般匯入的差別：有 `.notes-v2.json` 時保留原 id、資料夾排序與 6.4 的屬性。目前知識庫若非空，先自動匯出一份 ZIP 讓使用者下載，再詢問「取代」或「合併」（見待確認 #3）。

## 10. 設定頁「資料」分頁

```
資料
├── 儲存空間        （已有）用量、持久儲存狀態
├── 匯出            整個知識庫 ZIP ／ 包含未使用的附件 □
├── 匯入            Markdown 檔、資料夾、ZIP
├── 同步到資料夾    狀態：已同步 128 篇 · 2 分鐘前 ／ 選擇資料夾 ／ 停止同步
├── 從備份還原
├── 舊版資料        遷移報告 ／ 匯入 v1 備份 ZIP
└── 維護            （已有）重建索引、加入功能導覽筆記
```
側欄右鍵選單加「匯出為 Markdown」（筆記 → `.md`；資料夾 → ZIP）。

## 12. 測試

- **往返測試（核心）**：對每個支援的區塊與格式產生文件 → 匯出 → 匯入 → 再匯出，比對兩次 Markdown 相同；帶 manifest 時比對 ProseMirror JSON 相同
- **v1 夾具**：從 `v1-archive` 取真實範例內容（含 callout、`:::quote`、`a./i.` 清單、`![[id|名稱]]`、同名筆記、壞連結、SVG）做成測試資料，以 fake-indexeddb 建出 v1 結構的資料庫，驗證遷移結果與報告
- **中斷測試**：遷移 / 匯入在第 N 篇丟出錯誤，重啟後續傳，結果與一次完成相同、沒有重複
- **檔名測試**：特殊字元、Windows 保留名、超長標題、清理後撞名
- **鏡像**：以 OPFS（`navigator.storage.getDirectory()`，與 File System Access 同介面）在 Playwright 測試寫入、改名、刪除、外部修改保留、多分頁只有一個寫入者
- **E2E**：在測試網址先建出 v1 的 `WebObsidianDB` 再打開 v2 → 筆記出現、連結可點、附件顯示；匯出 ZIP 內容檢查
- **效能**：bench 腳本加入「匯出 1,000 篇」與「遷移 1,000 篇」量測

## 13. 切換到正式網址

1. 第 2 階段完成並通過測試
2. 在 Vercel 預覽網址用「匯入 v1 備份 ZIP」實際試一次你的真實資料，檢查遷移報告（不同網址讀不到 v1 的瀏覽器資料，所以預覽網址只能用 ZIP 測）
3. 切換當天：在 v1 匯出一份 ZIP 備份留存
4. **經你同意後**把 `v2` 合併進 `main`；正式網址開啟 v2 → 自動遷移同網址的 `WebObsidianDB`
5. v1 的資料庫保留不刪（第 2 階段不提供刪除）；確認無誤一段時間後，日後版本再提供「清除舊版資料」按鈕
